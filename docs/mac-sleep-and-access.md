# Macがスリープしていてもレポートに繋がるようにする

`serve_report.py` はMac上で動くローカルサーバーなので、**Macがスリープしていると
アクセスできない**。スマホから安定して繋がるようにするための設定と、繋がらない
ときの切り分け手順をまとめる。

Tailscaleの導入自体は [tailscale-setup.md](tailscale-setup.md) を参照。この文書は
「経路はあるのにMacが寝ていて繋がらない」「LAN経由で繋がらない」側の話を扱う。

前提として、この手順はMac/スマホの実機操作が必要なため、リモートのコーディング
環境からは実行できない。

## 結論: MacBookの場合は「起こす」のではなく「寝かせない」

Wake-on-LAN（マジックパケット）やApple TVのBonjourスリープ プロキシで
スリープ中のMacを起こす方法があるが、**ノート型Macは制約が大きい**。

| 接続方法 | スリープ解除 |
|---|---|
| 有線Ethernet（USB-Cアダプタ等）＋電源接続 | 動作する |
| Wi-Fi ＋ 電源接続 | 機種により不可。MacBook Airでは動作しなかった |
| バッテリー駆動（有線/Wi-Fi問わず） | **不可**（設定項目自体が無効） |

普段Wi-Fiで使うMacBookでは、**電源接続中はスリープさせない**設定にするのが
唯一の確実な方法になる。

```
sudo pmset -c sleep 0
```

`-c` は「電源アダプタ接続中の設定」の意味なので、バッテリー駆動時の電池持ちには
影響しない。元に戻すときは `sudo pmset -c sleep 20`（20分でスリープ）。

現在の設定は次で確認できる。`AC Power` セクションの `sleep` が `0` なら適用済み。

```
pmset -g custom
```

### 運用上の前提

- **電源アダプタを接続しておく** — 抜くとバッテリー側の設定が適用され、スリープする
- **蓋は開けたままにする** — 外部ディスプレイ非接続時は、この設定に関係なく
  蓋を閉じるとスリープする

この2つが守れない環境なら、常時起動できる別マシン（Mac mini等）にサーバーを
移すのが本来の解になる。`launchd/` のテンプレートはそのまま流用できる。

### 有線Ethernetを使う場合

有線接続なら Wake-on-LAN が正常に機能するので、スリープさせた上で必要な時だけ
起こす運用ができる。その場合は `sudo pmset -c sleep 20` に戻した上で、
「ネットワークアクセスによるスリープ解除」を有効にする。

```
pmset -g | awk '/womp/{print $2}'
```

`0` なら、**電源アダプタを接続した状態で** システム設定 →「バッテリー」→
「オプション...」→「ネットワークアクセスによるスリープ解除」をオンにする。
バッテリー駆動中はこの項目が出ないかグレーアウトする。

同じネットワークにApple TVやHomePodがあると、それがBonjourスリープ プロキシ
として動作し、`http://<ホスト名>.local:8766/` を開くだけでMacが起きる。
プロキシが見えているかは次で確認できる（`Ctrl-C` で終了）。

```
dns-sd -B _sleep-proxy._udp
```

## アクセスにはTailscaleのアドレスを使う

**LANのIPアドレス（`192.168.x.x`）をブックマークしない。** DHCPで変わるうえ、
有線とWi-Fiを切り替えると別のアドレスになる。

Tailscaleのアドレス（`100.x.y.z`）は経路が変わっても同じで、自宅でも外出先でも
そのまま使える。

```
tailscale ip -4
```

### Mac再起動後に繋がらなくなる場合

Tailscaleが自動接続されていない。メニューバーのTailscaleアイコン → 設定 →
**「Run unattended」** を有効にしておく。現在の接続状態は次で確認できる。

```
tailscale status
```

`Tailscale is stopped.` と出たら `tailscale up` で起動する。なお
`tailscale ip -4` は**停止中でも設定に残っているアドレスを返す**ので、
疎通確認には使えない。必ず `tailscale status` で見ること。

## 繋がらないときの切り分け

上から順に確認する。

**1. サーバーが起動しているか**

```
lsof -nP -iTCP:8766 -sTCP:LISTEN
```

何も出なければサーバーが落ちている。`launchd` で常駐させているなら
`/tmp/strava-report-server.log` を確認する。

**2. バインド先の確認**

`127.0.0.1:8766` と出た場合は他の端末から繋がらない。`.env` に
`REPORT_SERVER_HOST=auto` を設定してサーバーを再起動する。

`*:8766` と出ていても、**LAN上の端末からは繋がらない**点に注意。`auto` の場合、
`0.0.0.0` にバインドした上で接続元IPをTailscaleのレンジとループバックのみに
制限している（`serve_report.py` の `_client_allowed`）。listenしていることと
到達できることは別問題なので、`lsof` の結果だけで「公開できている」と判断しない。

**3. Tailscaleが両端で繋がっているか**

```
tailscale status
```

Macとスマホの両方が一覧に出ていることを確認する。スマホ側のTailscaleアプリが
オフになっているのが、外出先で繋がらない最も多い原因。

**4. LAN経由で繋ぎたい場合のIP確認**

`ipconfig getifaddr en0` が空を返すことがある。`en0` はWi-Fiだが、有線アダプタを
繋いでいるとそちらにIPが付くため。実際に割り当てられているアドレスは次で分かる。

```
ifconfig | grep "inet " | grep -v 127.0.0.1
networksetup -listallhardwareports
```

なおLAN経由で使うには `.env` に `REPORT_SERVER_HOST` として**明示的なIPアドレス**
を書く必要がある（`auto` では接続元制限に弾かれる）。ただし前述の通り推奨しない。

**5. ファイアウォール**

```
/usr/libexec/ApplicationFirewall/socketfilterfw --getglobalstate
```

`enabled` の場合、該当プロセスの着信接続が許可されているかをシステム設定 →
「ネットワーク」→「ファイアウォール」→「オプション」で確認する。

## 補足: Wi-FiのMACアドレスについて

`ifconfig en0` で表示されるMACアドレスは、iOS/macOSの「プライベートWi-Fiアドレス」
機能によりネットワークごとにランダム化されていることがある。先頭オクテットの
下位2ビット目が立っていれば（`fa:` など）ランダム化されたアドレス。

このアドレスはWake-on-LANの宛先やルーターのDHCP予約には使えない。実際の
ハードウェアアドレスは `networksetup -listallhardwareports` で確認する。
